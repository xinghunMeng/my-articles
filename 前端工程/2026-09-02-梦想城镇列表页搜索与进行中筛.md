# 梦想城镇列表页搜索与「进行中」筛选重构复盘

## 问题背景

梦想城镇小程序的列表页承载镇长互助社区的核心流转：用户发布求助帖、按关键词检索自己缺的卡牌或产品、再进入详情帮助他人。该页面存在两类问题：

1. 搜索准确率极低，用户反馈「很不准」。
2. 大量已过期的产品求助仍出现在「进行中」列表，且仍可发起帮助。

两类问题均源于前期的查询构造过于简单，未覆盖数据的真实分布。

## 技术方案

### 搜索字段扩展与正则转义

原 `buildWhere` 仅匹配 `title` 与 `gameId`，而卡牌名存于 `haveCards[].name` / `wantCards[].name`，产品名存于 `items[].name`，正文存于 `content`。扩展为 6 字段 `_.or` 匹配：

```js
const kw = escapeRegexp(keyword.value.trim())
buildWhere = _.or([
  { title: db.RegExp({ regexp: kw, options: 'i' }) },
  { content: db.RegExp({ regexp: kw, options: 'i' }) },
  { gameId: db.RegExp({ regexp: kw, options: 'i' }) },
  { 'items.name': db.RegExp({ regexp: kw, options: 'i' }) },
  { 'haveCards.name': db.RegExp({ regexp: kw, options: 'i' }) },
  { 'wantCards.name': db.RegExp({ regexp: kw, options: 'i' }) },
])
```

用户输入 `(`, `*`, `[`, `?` 等特殊字符会使云库正则非法报错，需转义：

```js
function escapeRegexp(s) {
  return s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
}
```

### 过期过滤与可选字段兜底

「进行中」原仅按 `status:'open'` 过滤。产品求助带 `expiryAt` 倒计时，过期后 `status` 仍为 open，需显式排除。用 `conditions` 数组统一拼装：

```js
if (filterStatus === 'open') {
  conditions.push({ status: 'open' })
  conditions.push(_.or([
    { expiryAt: _.exists(false) },   // 旧数据缺字段
    { expiryAt: _.eq(0) },          // 卡牌帖永久有效
    { expiryAt: _.gt(Date.now()) }, // 产品帖未过期
  ]))
}
```

仅排除「产品帖 `expiryAt` 落在 (0, now]」的区间。

## 踩坑记录

- **Taro 4 受控输入不同步**：`input` 同时写 `v-model` 与 `@input` 时 `keyword` 不同步，表现为输入后列表闪现却显示全部。改为 `:value="keyword"` + `onSearchInput(e) { keyword.value = (e.detail.value) || '' }`，值路径为 `e.detail.value`。
- **可选字段等值过滤漏数据**：初版仅 `_.eq(0)`，漏掉无 `expiryAt` 字段的旧卡牌帖，导致整类帖从列表消失。补 `_.exists(false)` 兜底。
- **模板调用未导出纯函数白屏**：`groupByTheme` 重构后漏加 `setup return`，模板调用得 `undefined` 整页白屏。模板直接调用的纯函数必须在 `setup return` 显式导出。

## 工程复盘

列表查询的质量取决于是否真实覆盖字段分布与数据演进（旧数据缺字段）。查询构造应集中到 `buildWhere` 用 `conditions` 数组拼装，便于统一加正则转义与状态过滤。Taro 4 + Vue3 小程序中 `input` 受控一律用 `:value` + `@input` 显式同步，不依赖 `v-model`。
