# AI 生图水印污染转线稿功能的排查与防御式去水印方案

## 问题背景

AR 绘图桌小程序提供"图片转线稿"功能：用户上传图片，本地 canvas 经 Otsu 二值化转为黑白线稿，叠在摄像头画面上照着描。近期接入 AI 生图能力后，发现转出的线稿里偶尔出现一行无关文字"AI生成"。

根因：腾讯云 AI 生图默认在返回图右下角压入显式标识"图片由 AI 生成"。该标识为深色文字压浅色底，灰度值低。Otsu 二值化按全局阈值将像素划分为前景（黑）/背景（白），低灰度的水印文字被归入前景，于是在线稿里被完整保留——用户描摹时会描到这几个字。

## 技术方案

去水印需关闭官方 logo。TC3 网关层 API 提供 `LogoAdd` / `LogoParam` 开关，但微信 `cloud.ai` 的 SDK 文档未暴露这两个参数。经验表明该链路会透传若干"文档未列但可生效"的字段（`seed`、`footnote`、`enable_thinking` 均已验证），因此采用探针式传参：

```js
// cloud/functions/generateImage/index.js
const input = {
  model: 'hunyuan-image',
  prompt,
  size: '1024x1024',
  footnote: '',   // 试探：清空水印注解
  logo_add: 0,    // 试探：关闭官方 logo
};

let noWm = true;
try {
  res = await imageModel.generateImage({ ...input });
} catch (e) {
  noWm = false;
  console.warn('去水印参数被拒，回退带水印重试', e);
  res = await imageModel.generateImage({ model: 'hunyuan-image', prompt, size: '1024x1024' });
}
console.log('[generateImage] noWm =', noWm);
```

## 踩坑记录

- `footnote: ''` 有被厂商校验拒绝的风险（文档将其定义为"水印"，未说明可为空）。一旦拒绝会整次调用失败，因此必须 try/catch 回退到不带这两个字段的原参数，确保"去水印"实验不破坏已跑通的生图功能。
- 判读靠云端日志标记 `noWm`：真且图上无水印=生效；真但图上还有=字段名不对；假（有 warn）且图上还有=参数被拒但回退成功。

## 工程复盘

AI 产物不是流程终点。它还要被二值化、OCR、或喂给下游模型。任何"看似无害的附加信息"（水印、边框、EXIF）都可能在下游被放大成缺陷。写 AI 管线时应当站在下游消费者视角反推上游每个字段。

合规上，国内《人工智能生成合成内容标识办法》（2025-09-01 施行）要求 AI 内容显式标识。最终方案：图片层面去除像素水印，入库时写入 `aiGenerated: true`，UI 层绘制"AI 生成"角标。标识不丢、模板干净。
