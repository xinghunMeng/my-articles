# browser-skill 替代 puppeteer 的 Cocos 预览 UI 自动化测试

## 问题背景

Cocos Creator 3.8.8 项目（妖灵守卫，Q 版山海经塔防）的 UI 回归测试此前基于 puppeteer-core。两个痛点长期存在：一是 headless 跑 WebGL 需要维护 swiftshader 启动参数，环境脆弱；二是截图之后只能人眼走查，像素级问题（如按钮贴边框 2px）无法被程序化发现。本文记录切换到 browser-skill（bsk）的完整方案，以及从截图走查升级到数值断言的工程实践。

## 技术方案

### bsk 会话工作流

bsk 驱动真实 Chromium（浏览器扩展连接），核心流程：

```bash
bsk status                                   # 确认 daemon 在跑、浏览器已连接
bsk session start --width 1280 --height 800  # 输出 4 字母 session id
bsk navigate http://localhost:7456 --session <id> --wait-until load
bsk wait-ms 5s                               # 等 WebGL 资源加载
bsk screenshot --session <id> --out <path>   # 视觉走查
bsk evaluate "<js>" --session <id>           # 引擎状态 / 节点属性断言
bsk session stop <id>                        # 必须关闭
```

### evaluate 模拟真实鼠标点击

游戏按钮是纯代码创建的 Node（`new Node('btn')` + TOUCH_START 事件），不是 cc.Button 组件，且 canvas 内元素不进 snapshot aria 树，bsk click 无法命中。方案：evaluate 内遍历节点树按 Label 文本找按钮，算坐标后派发事件：

```js
// 1. 按 Label 文本找按钮（label 在子节点 'lb'）
let btn = null;
const walk = (n) => { if (btn || !n) return;
  if (n.name === 'lb' && n.getComponent(cc.Label) && n.getComponent(cc.Label).string === '开 始 游 戏') { btn = n.parent; return; }
  (n.children || []).forEach(walk); };
walk(cc.director.getScene());

// 2. 世界坐标 → CSS clientX/Y（用 Node 原生 API，避开 cc.UITransform 引用异常）
const cam = scene.getChildByName('Canvas').getChildByName('Camera').getComponent(cc.Camera);
const wp = btn.getWorldPosition(new cc.Vec3());
const sp = cam.worldToScreen(wp);
const canvas = document.getElementById('GameCanvas') || document.querySelector('canvas');
const rect = canvas.getBoundingClientRect();
const clientX = rect.left + sp.x * (rect.width / canvas.width);
const clientY = rect.top + rect.height - sp.y * (rect.height / canvas.height);

// 3. PointerEvent + MouseEvent 双发
const base = { clientX, clientY, button: 0, buttons: 1, pointerId: 1, pointerType: 'mouse', bubbles: true, cancelable: true, view: window };
canvas.dispatchEvent(new PointerEvent('pointerdown', base));
canvas.dispatchEvent(new MouseEvent('mousedown', base));
canvas.dispatchEvent(new PointerEvent('pointerup', Object.assign({}, base, { buttons: 0 })));
canvas.dispatchEvent(new MouseEvent('mouseup', Object.assign({}, base, { buttons: 0 })));
```

### 数值断言体系

截图走查对像素级问题有天然盲区（1280px 下 2px 不可辨），因此每个页面追加 evaluate 数值断言：

| Step | 断言 | 阈值 |
|---|---|---|
| 4.5 | 元素到容器边界内边距 | ≥ 15px |
| 4.6 | 同类元素对齐一致性（按 centerX 聚类） | 组内偏差 ≤ 2px |
| 4.7 | 文字溢出估算（中文 ≈ fontSize/字符） | 超框 +4px 容差 = warn |
| 4.8 | 颜色语义（ok=绿系 / danger=红系） | 增益按钮用危险红 = 语义错乱 |
| 4.9 | 画布边界（容器四边 vs Canvas 世界位置） | ≥ 5px |

## 踩坑记录

- **编辑器最小化也停编译**：改 .ts 后 `temp/programming/packer-driver/targets/preview/chunks/` 为空、mtime 停旧 → 判断脚本 `find chunks -name "*.js" -newer <改的.ts>` 无输出 = 编辑器没在编译；恢复窗口后自动增量编译，浏览器自动拉新 bundle，bsk 端不需要 reload。
- **evaluate 里 `getComponent(cc.UITransform)` 返回 null**（引用异常），改用 `node.getWorldPosition(new cc.Vec3())` 绕过。
- **bsk screenshot 父目录不存在**返回 exit 2，且错误提示误导为 daemon 未运行；先 `mkdir -p <dir>` 即可。
- **断言模板自身 bug**：4.6 按行分组对 2+2+1 金字塔布局产生 false positive（左右列左缘天然不同），改为按 centerX 聚类后 dev=0；4.8 颜色阈值需先打印实际 RGB 校准（C.ok 墨绿 g=95 曾漏过 g>100 阈值）。

## 工程复盘

游戏 UI 测试流水线 = 视觉走查（结构性/大尺度）+ 数值断言（像素级/语义级）+ 引擎状态查询（cc.director）。核心结论：截图只适合"看"，像素级必须"量"；自动化测试工具本身也需要上岗验证。整套方案沉淀为 skill `cocos-preview-bsk-test`（含 HTML 报告生成），与 `cocos-dev-guide`（写 UI 防坑）、`cocos-project-scaffold`（搭骨架）形成三 skill 分工，已发布至 SkillHub 与 github.com/xinghunMeng/cocos-skills。
