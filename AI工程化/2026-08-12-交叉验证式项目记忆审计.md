# 交叉验证式项目记忆审计：让 MEMORY.md 与代码真相保持一致

## 问题背景

在 AI 辅助开发模式下，AI 的上下文来自项目内的长期记忆文件（MEMORY.md）。该文件一旦与代码真相脱节，AI 会持续输出基于过期信息的错误建议，且错误具有"一本正经"的迷惑性——文档语法正确、逻辑自洽，唯独与代码不一致。

本次审计对象：梦想城镇攻略小程序（Taro 4 + Vue 3 + Less + 微信云开发）。项目经历产品方向转向（提醒工具 → 三消攻略平台），迭代频繁，长期由 AI 协作推进，记忆文件与代码的偏差随时间累积。

## 审计方法：交叉验证

核心原则：记忆文件中的每一条断言，必须能在代码或配置中找到客观证据。逐项验证手段如下：

| 记忆条目类型 | 验证命令/方式 |
| --- | --- |
| 项目路径 | `ls` 实际目录结构 |
| 云函数清单 | `ls cloudfunctions/` |
| tabBar 数量与顺序 | 读取 `app.config.js` |
| 页面/数据结构 | `ls src/pages`、数据文件计数 |
| 架构事实（上传通道） | 对照代码中的请求 URL |

## 审计结果：五类典型漂移

1. **路径漂移**：记忆记录 `/Users/wn/Documents/h/dream-town/`，实际根目录为 `/Users/wn/Documents/my/dream-town/`（补 `my/`）。路径错误直接导致 AI 定位文件失败。
2. **清单缺漏**：云函数仅记录 `sendReminder`，实际存在 3 个：`getMyOpenId` / `sendReminder` / `match3Guide`。清单不全会让 AI 在排查时忽略存在的能力。
3. **配置过时**：tabBar 记录为 3 个，实际为 4 个（首页→我的提醒→资料库→三消攻略），资料库为产品转向后新增。
4. **架构事实错误**：记忆写"攻略视频走云数据库 userVideos（云存储）"，实际已改为自建后端 `https://getoffer.alleria.cn/api/upload`。此类错误风险最高——排障时按错误架构排查会完全跑偏，且该通道强依赖外部服务可用性，属于需要重点维护的架构事实。
5. **环境残留**：视频压缩脚本记录为 Windows 路径（`H:\small\...`、`D:\...`），当前 macOS 开发机不适用。环境变更后未同步，属于"可运行但已失效"的条目。

另有**漏记**：2026-07-30 落地的"资料库详情页反向关联（可用于）"功能未写入记忆。

## 非纠错观察

首页注释仍写"提醒助手为核心功能"、app.config.js 导航栏标题仍为"梦想的城镇收菜助手"——与产品已转向三消攻略的旧叙事残留，列入待清理项。代码级旧文案与记忆文件漂移同源，都是"变更未闭环"。

## 工程复盘

- 交叉验证是文档治理的最小可靠手段：不依赖印象，用 `ls` / 读配置文件等客观证据校验每条记忆。
- 文档漂移按风险分级：架构事实错误 > 清单缺漏 > 路径/环境残留，治理优先级应与之对齐。
- 将"变更即更新记忆"固化为工作流（改架构/功能/脚本后同步记忆），可显著降低漂移累积速度。

工程总结：AI 协作模式下，记忆文件就是输入质量，输入质量决定输出质量；交叉验证式审计是把文档漂移当技术债偿还的可行路径。
