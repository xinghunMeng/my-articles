# 微信小游戏 T 字挑战：拖拽钳制自引用 bug 与无设备自动化测试流水线

category: 游戏开发

## 问题背景

微信小游戏「T 字挑战」是一个四巧板（T 字之谜）拼图游戏，纯 canvas 渲染、无第三方引擎，88 关、看广告解锁答案、计时。核心交互是拖拽 4 块板到目标轮廓。用户真机预览反馈：拖动一块到屏幕边界时，块会向相反方向移动（手指向右、块向左）。

## 技术方案

拖拽流程：`onTouchMove` 收到触摸坐标，屏幕坐标转 unit 坐标，更新块位置，`clampPiecePos` 钳制到可视区，重绘。绘制走 `requestAnimationFrame` 循环。布局按本关轮廓与托盘的实际包围盒动态计算缩放与居中，按钮贴 `safeArea`。

## 踩坑记录

`clampPiecePos` 初版实现：

```js
function pieceUnitBounds(p, x, y) {
  // 用目标位置 (x,y) 算包围盒
  const bb = /* 由 x,y 推导 maxX/minX ... */
  return bb
}
function clampPiecePos(p, x, y) {
  const bb = pieceUnitBounds(p, x, y)   // 目标位置
  const minUX = (safeArea.left + pad - ox) / scale
  const maxUX = (safeArea.right - pad - ox) / scale - bb.maxX
  return { x: Math.min(Math.max(x, minUX), maxUX), y: /* 同理 */ }
}
```

问题：`maxUX` 依赖 `bb.maxX`，而 `bb.maxX` 来自目标位置 `x`。于是钳制上界随目标 x 反向变化（斜率 -1）。数值复现：块越过边界后，Δpiece 从 +0.704 翻转为 -0.704，一路反甩到屏最左。这是输入变量与边界同源导致的自引用负反馈。该 bug 同样污染 `loadLevel` 初始摆放，把块挤到角落。

修复：边界用固定锚点 (0,0) 算块的相对包围盒偏移，与目标位置解耦：

```js
function clampPiecePos(p, x, y) {
  const bb = pieceUnitBounds(p, 0, 0)   // 相对偏移，与目标无关
  const minUX = (safeArea.left + pad - ox) / scale
  const maxUX = (safeArea.right - pad - ox) / scale - bb.maxX
  return { x: Math.min(Math.max(x, minUX), maxUX), y: /* 同理 */ }
}
```

边界成为不变量，块到边界钉住不回弹。375x667 / 375x812 两机型数值验证通过。

## 工程复盘

1. 无设备自动化测试：写 `tools/test_game.js`，mock `wx.createCanvas` / `getSystemInfoSync` / `onTouchStart` 等 API 及 canvas ctx（Proxy 空操作），`require('../game.js')` 真跑 init，复刻布局常量把 unit 坐标换算成屏幕坐标发触摸事件，自动通关 88 关。逻辑回归从此 node 一键跑，不依赖真机。
2. 打包纪律：小游戏运行时不可 `require` npm 包或本机绝对路径。原把 polygon-clipping 轮廓计算放运行时，打包后报 `module '.../node_modules/polygon-clipping.js' is not defined`。改为构建时算：`tools/build_levels.js` 用 polygon-clipping 求 60 关精确并集轮廓，归一化写死进 `utils/gv2_levels.js`，运行时只 `require` 相对路径。
3. 兼容性：`requestAnimationFrame` 在小游戏是全局函数（非 `wx.`），`getSystemInfoSync` 新版基础库废弃，统一用全局优先、`wx` 兜底、`setTimeout` 最后兜底的三段式。

工程总结：钳制与边界计算必须解耦被钳制变量；外部依赖只能存在于构建脚本，产物以数据形式固化。更多见 blog.alleria.cn。
