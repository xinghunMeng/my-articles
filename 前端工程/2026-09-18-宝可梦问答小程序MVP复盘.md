# 从市场调研到 MVP：宝可梦问答小程序的数据管线与题库工程

## 问题背景

需要从零做一款宝可梦百科问答小程序（微信原生 + 云开发）。核心难点不在 UI，而在三块工程问题：第一，数据从哪来、怎么稳定抓全；第二，题库如何可复现地大规模生成且干扰项合理；第三，判分逻辑放哪、如何防作弊。本文记录这一天的实现与踩坑。

## 技术方案

### 数据管线

数据源为 PokeAPI 公开数据。用 Node 原生 `fetch` 并发 16 路抓取 species 与 pokemon 各 1025 条，输出单文件 `pokemon.json`（约 636K），包含中文名、属性、六项种族值、身高体重、世代、去重描述、进化链。关键实现：

```js
const concurrency = 16;
async function fetchAll(ids) {
  const results = [];
  for (let i = 0; i < ids.length; i += concurrency) {
    const batch = ids.slice(i, i + concurrency);
    const part = await Promise.all(batch.map(fetchOne));
    results.push(...part.filter(Boolean));
  }
  return results;
}
```

注意：语言标签是小写 `zh-hans`，写成 `zh-Hans` 会返回空；九世代新宠多无中文描述，题池需按"有描述"过滤，实际 722 只进入图鉴描述题池。描述文本含全角空格与全角数字（如"１４００米"），出题清洗时要归一化。

### 题库生成

固定随机种子（20260904），保证每次生成结果一致、可审计。生成 1212 题，三类题型：图鉴描述猜 800、之最排行 240、属性克制 172。第一版干扰项与主答案差异过大，用户反馈"一眼看出答案"。重做后引入相似度打分：同主属性 +4、同副属性 +2、同世代 +2、老世代人气 +1、体型接近 +1，使 94% 干扰项与主答案同主属性；之最题干扰项数值不低于答案的 82%。去重键取"题干 + 选项集合"，避免重复出题。

### 小程序架构与服务端判分

原生小程序 + 微信云开发，4 个页面加 2 个云函数：`getDailyQuiz`（按日期种子取当日题）、`submitResult`（服务端判分、连胜、百分位）。安全要点：答案不下发客户端；只收当日提交并去重；同日题干去重防止"攻击种族值最高"出现两道重复题；判分在服务端完成，前端无法获知正确答案。

## 踩坑记录

- PokeAPI 语言标签大小写敏感，`zh-Hans` 拿不到数据，须用小写 `zh-hans`。
- 描述文本含全角数字/空格，未归一化会导致题干展示异常。
- 干扰项过于直白，需以相似度打分强化，否则题目没有区分度。
- 一次性 `node -e` 脚本残留空 while 死循环（guard 不递增）导致超时被后台化；验证脚本写文件执行更稳。

## 工程复盘

做小程序不是写页面，而是"调研 → 数据 → 题库 → 架构 → 安全"的完整链路。需求与版权排查前置，能避免后期返工；数据管线与题库生成用固定种子保证可复现，是后续审计与质量把控的基础。更多细节见博客 https://blog.alleria.cn 。
