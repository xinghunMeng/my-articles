# 复刻 pokequizz 的微信小程序：剪影渐进揭示与工程纪律复盘

## 问题背景

pokequizz 是海外一个宝可梦 quiz 站点。目标是在微信小程序里复刻其核心玩法，其中"剪影猜"要求：起始只露局部剪影，用户每猜错一次逐步拉远露出更多，同时按尝试次数揭示目标主色，最终揭晓彩色立绘。难点在于交互语义澄清，以及揭示时序的确定性。

## 技术方案

- 缩放：`computeZoom = over ? 1 : Math.max(1, 2.0 - wrongs * 0.2)`，6 次机会；`.stage-inner` 设 `transform-origin: 50% 30%`（头部锚点），用 CSS transform 缩放，外层 `overflow:hidden` 裁切。
- 颜色揭示时序 `revealedColorsAt(attempts)` 按"尝试次数"而非"错题数"计算：`attempts>=4` 给 colors[0..2]，`>=2` 给 colors[0]；双槽 PRIMARY/SECONDARY。
- 主色提取 `gen_sil_colors.py`：Pillow 只取不透明像素，剔除 `max<40` 且近中性的纯黑轮廓（眼睛/描边），量化直方图（桶 STEP=28）加权，贪心取与已选距离 `>=90` 的 top2，写入 `sil_pool.json`。
- 锯齿治理：剪影 PNG 由二值 palette 改为 LA 模式（灰度+alpha），保留原图边缘 alpha 渐变，放大后边缘平滑。
- 防御档案 `defenseProfile(types)`：从 PokeAPI `damage_relations` 生成的 `type_chart.json` 计算被克制/抵抗/免疫分组；注意 0 倍免疫曾被 `||1` 吞掉，改为 `v==null?1:v`。

## 踩坑记录

1. 需求澄清：用户口中的"放大"实为"缩小缩放比例以看到更多"——相对可视区域而非绝对。前后 4 版方向反复，最终以"先露头部一角→渐进展开"对齐 pokequizz 观感。
2. 契约误用：云函数返回 `revealedClues` 是对象（按错次算好的揭示子集），前端 `buildShownClues` 误当数组 `filter`，运行期报 `(attempts||[]).filter is not a function`。改为遍历 `CLUE_ORDER` 检查 `k in revealedClues`。
3. 批量编辑陷阱：用 Edit 批量改 8 个云函数出现"报告成功但未写入"，导致 `pickBySeed`/`POOL` 引用残缺。改为可验证脚本整体替换函数体，并用 mock `wx-server-sdk` 的 `test_sprint.js`/`test_daily_mode.js` 跑通 8/8 才放心。
4. 0 倍免疫被吞：`core` 里 `||1` 把免疫倍率 0 吞掉，改为 `v==null?1:v`。

## 工程复盘

测试要覆盖"状态变化后的再读取"路径，只测首次 get 抓不到渐进揭示类 bug；批量改动必须可验证收口。最终剪影/彩图共 2050 个确定性文件上 CDN（jsDelivr 镜像拉原图），主包瘦身到只留首页图。

副业项目的工程水位，决定了它能不能写进简历。把需求澄清、契约约束、测试纪律当默认项，比功能本身更值钱。
