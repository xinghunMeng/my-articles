# upload-server 配置驱动重构与服务器 PM2 进程收敛复盘

## 问题背景

腾讯云 Ubuntu 服务器（49.232.128.58）承载博客、刷题站、面试站、提醒服务等多个项目，长期缺乏统一治理：

- 文件上传接口逻辑硬编码在 `index.js`，新增素材目录需改源码并重启服务；
- root 与 ubuntu 两套 PM2 daemon 并存，进程归属混乱；
- SSH 登录依赖手动输入密码，无配置文件。

目标是在不中断线上服务的前提下完成三件事：SSH 免密、upload-server 配置驱动化与防目录穿越、PM2 进程统一收敛到 ubuntu 账号。

## 技术方案

### 1. SSH 免密接入

- 登录账号为 `ubuntu`（腾讯云默认），root 公钥直连被拒属正常。
- 私钥 `~/.ssh/alleria.pem` 初始权限 644 被拒，修正为 600。
- 写入 `~/.ssh/config`：

```
Host drew-server
  HostName 49.232.128.58
  User ubuntu
  IdentityFile ~/.ssh/alleria.pem
  IdentitiesOnly yes
```

此后 `ssh drew-server` 直连免密。

### 2. upload-server 配置驱动重构

原实现 Express + multer，监听 `127.0.0.1:3100`，nginx 将 `getoffer.alleria.cn/api/` 反代至 3100，`/images/` 指向静态根。

重构要点：

- 目录映射从硬编码抽取为 `config.json` 白名单：

```json
{"video":"images/video","avatar":"images/avatar","ar":"images/AR"}
```

相对 `STATIC_ROOT=/var/www/getoffer-static`。

- URL 由 `BASE_URL/<rel>/<filename>` 自动拼装，不再硬编码前缀。
- 未知 `type` 返回 400 并列出可用值；启动时自动 `mkdir -p` 目标目录。
- 增加目录越界校验，防止 `../../` 穿越至 STATIC_ROOT 之外。

新增素材类型仅需 `config.json` 加一行 + `pm2 restart upload-server`，无需改代码。

### 3. PM2 进程收敛

- 发现 root（`/root/.pm2`）与 ubuntu 两套 PM2 daemon 共存，`images/` 被多项目共享。
- 将 `interview-site`（Nuxt，端口 3000）从 root PM2 迁至 ubuntu PM2：`sudo pm2 stop interview-site` → ubuntu `pm2 start` 同参 → 本地 3000 返回 200 → `sudo pm2 delete` + `save`。
- 收敛后 ubuntu PM2 统一管理 4 个进程：`reminder-service`(cluster)、`upload-server`、`blog`、`interview-site`。

## 踩坑记录

- **pem 权限**：644 会被 SSH 拒绝，必须 600。
- **两套 PM2**：root 侧 daemon 仍存活但无进程，运维时需明确 `export PATH=/home/ubuntu/.npm-global/bin:$PATH` 调用 ubuntu 的 pm2，避免误操作 root 实例。
- **共享静态目录**：`images/` 下 book/crops/goods/icons/materials/pokemon/share 等多项目混用，新增 type 前需确认不与既有目录冲突。
- **重构纪律**：先 `cp index.js index.js.bak-20260906`，实测新 type 上传成功并自动建目录后还原清理，避免遗留测试文件。

## 工程复盘

1. 配置驱动优于硬编码：能力扩展从"改码发版"降为"配置 + 重启"。
2. 安全是重构的自然产出：白名单 + 越界校验把"能传哪"由隐式变为显式约束。
3. 进程归属单一化：收敛到单一账号的 PM2，显著降低运维心智负担与误操作风险。
4. 灰度与回滚：备份 + 实测 + 还原的闭环，让无测试环境的服务端改动也能低成本试错。
