# Taro Vue3 微信小程序线稿库首页：分页、分类缓存与回到顶部的工程复盘

category: 前端工程

## 问题背景

AR 绘图桌是一款 Taro 4 + Vue 3 的微信小程序，首页线稿库是高频页面。初期实现存在三类体验缺陷：列表触底无续加载、切换分类重复请求第一页、长列表缺少回到顶部入口。另有两个编译期告警需治理。本文记录对应的工程方案。

## 技术方案

### 分页与触底加载

基于 `scroll-view` 实现，每页 20 条：

```js
// scroll-view 配置
<scroll-view
  scroll-y
  :scroll-into-view="scrollIntoView"
  :lower-threshold="150"
  @scrolltolower="loadMore"
  @scroll="onScroll"
/>
```

`loadMore` 内置两个闸门避免并发：

```js
async function loadMore() {
  const c = caches[activeCat.value]
  if (c.loading || !c.hasMore) return      // 加载中 / 无更多，直接返回
  c.loading = true
  const res = await fetchLinearts(activeCat.value, c.page)
  c.list.push(...res.items)
  c.page += 1
  c.hasMore = res.hasMore
  c.loading = false
}
```

### 分类内存缓存

用 `reactive` 对象按分类缓存已加载数据，避免重复请求：

```js
const caches = reactive({})  // key: 分类名 -> { list, page, hasMore, loading }

function switchCat(cat) {
  if (caches[cat]) {           // 命中缓存：零请求直接切换
    activeCat.value = cat
    scrollToTop()
    return
  }
  caches[cat] = { list: [], page: 1, hasMore: true, loading: false }
  activeCat.value = cat
  loadFirstPage(cat)
}
```

### 回到顶部（两段式）

`scroll-into-view` 对同一锚点 id 不变时不触发，需先清空再赋值：

```js
function backToTop() {
  scrollIntoView.value = ''          // 先清空
  nextTick(() => { scrollIntoView.value = 'page-top' })  // 再置锚点
}
```

锚点 `id="page-top"` 置于 hero 区域，`scroll-view` 开启 `scroll-with-animation` 平滑回顶。

### 强制刷新时机

`useDidShow` 中仅在来源页为素材管理页或当前分类无缓存时重拉第一页，否则复用内存缓存：

```js
useDidShow(() => {
  const pages = Taro.getCurrentPages()
  const prev = pages[pages.length - 2]?.route
  if (prev === 'pages/admin/index' || !caches[activeCat.value]) {
    loadFirstPage(activeCat.value)
  }
})
```

## 踩坑记录

1. `app.json` 报错 `无效的 window['glassEaselWebview']`。经查 glass-easel 迁移文档，`glassEaselWebview` 是 app.json 顶层字段，与 `pages` / `window` 平级，非 `window` 子项。移出 `window` 至顶层即解决。
2. Skyline 渲染下 wxss 大量 `-webkit-/-ms-` 前缀 warning。源码无前缀，系 Taro 默认开启的 autoprefixer 按 browserslist 注入，而 Skyline 仅识别标准属性。在 `config/index.js` 中显式关闭 mini 端 autoprefixer：

```js
// config/index.js
mini: {
  postcss: {
    autoprefixer: { enable: false }   // h5 端配置保留不动
  }
}
```

注意：修改 `config/index.js` 需重启 `npm run dev:weapp` 才生效。Taro 的 `mini.postcss` 不写 `autoprefixer` 不等于关闭，默认仍开启，必须显式 `enable: false`。

## 工程复盘

前端列表页的体验问题，本质是状态与请求的管理：缓存策略决定重复请求是否被消灭，回顶交互决定长列表是否可用，编译告警是框架迁移的显式信号而非噪音。会话级内存缓存对该场景已足够，不必过早引入持久化。相关项目主页见 blog.alleria.cn。
