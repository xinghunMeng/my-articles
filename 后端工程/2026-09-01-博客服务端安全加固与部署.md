# 博客服务端安全加固与部署流水线复盘

## 问题背景

个人博客（Node.js + Express + Markdown，blog.alleria.cn）作为求职作品集入口，对外暴露面未经系统审查。一轮安全体检发现四类问题：slug 路径穿越、列表排序错乱、静态资源过度暴露、部署端口错配。

## 技术方案

1. slug 输入校验：实现 sanitizeSlug()，正则限定为 `[\w\u4e00-\u9fa5\-_]`，应用于 /post/:slug、/api/posts/:slug 的 GET/PUT/DELETE 以及新建文章 slug 生成，共 5 处入口统一收敛。
2. 列表排序：getAllPosts() 由文件名字母序改为按 frontmatter date 字段倒序，`b.date.localeCompare(a.date)`，解决中文 slug 乱序。
3. 静态资源白名单：将 `express.static(__dirname)` 替换为仅挂载 css/js/projects/admin 四个子目录，根目录仅显式路由 index.html、about.html、resume.pdf；删除历史遗留的 blog.html 与 posts/ 静态页，新增 301 将 /blog.html→/blog、/posts/:slug→/post/:slug。
4. 部署链路：本地 commit 推 Gitee，服务器 git pull、npm install --production、pm2 restart blog。

## 踩坑记录

- 静态目录过度暴露：`express.static(__dirname)` 使 server.js、package.json、posts-md 源码均可被 HTTP 直接访问（实测 200），白名单化后 /server.js 返回 404。
- 部署端口错配：Nginx 反代 127.0.0.1:3002，但 server.js 默认 3000，依赖 dotenv 读取 .env 的 PORT=3002 才正确。直接 `node server.js` 启动会因端口不符导致 502，必须用 pm2 的 blog 进程（cwd 指向项目根）以保证 .env 被加载。
- 本地 curl 验证时本机代理会拦截 localhost 返回 502，需用 `curl --noproxy '*'` 绕过。
- 遗留未修项：express.static 仍托管部分目录（已收敛）、无登录频率限制，列为后续。

## 工程复盘

安全加固的核心是最小可见面原则：任何用户可控输入拼入文件路径、或决定静态资源暴露范围的代码，都应默认收紧。验证以实测路由响应为准（16 条路由全符合 200/301/404），而非仅靠代码审查。相关实践见 blog.alleria.cn。
