
# 个人博客导航错位修复：移动端遮罩样式泄漏到桌面端布局

category: 前端工程

## 问题背景

个人博客（Node.js Express + Markdown）首页桌面端出现导航错位：🌙 深色模式按钮与内容区右缘不对齐，被挤向中间。调整 padding/flex 均无效，问题与当前改动无关。

## 根因分析

通过开发者工具逐一标注导航栏子元素，发现一个零宽度空元素 `.nav-overlay` 占据 `justify-content: space-between` 布局的最右位置，将导航整体向左挤压。

```css
/* 原实现：position: fixed 只声明在媒体查询内 */
.nav-overlay { display: none; }
@media (max-width: 768px) {
  .nav-overlay { display: block; position: fixed; inset: 0; z-index: 999; }
}
```

关键认知：**媒体查询内的样式并不"绑定"特定宽度**。桌面端 `.nav-overlay` 仍是普通元素（`display: none` 未加，实际以 0 宽空子项参与 flex 布局），其 `position: fixed` 在桌面断点下从未生效，导致其作为 flex 子项占用 space-between 的锚点位置。

## 修复方案

1. 将 `position: fixed` 提升为全局基础样式（脱离 flex 文档流），媒体查询仅保留显示/隐藏逻辑
2. 删除媒体查询中的重复 `position: fixed` 规则
3. `.nav-inner` 增加 `padding-bottom: 1.25rem`，避免底边框贴住导航文字
4. header 底边框由 `.site-header` 通栏迁移至 `.nav-inner`（960px 内容约束内），使分隔线宽度与内容区一致

## 同批改版

- hero 区精简：删除「📝 博客」「了解更多 →」链接；「下载简历」由按钮样式改为与 Email/GitHub 一致的纯文字链接
- 新增 `projects/blog-system.html` 作品集详情页（返回链接 → 标题+在线版链接 → 简介 → 技术栈 tags → 核心能力 5 条），首页卡片改为跳详情页

## 部署与运维

- 流程：`git commit → push Gitee → 服务器 git pull → pm2 restart blog`（pm2 位于项目 `node_modules/.bin`，非全局）
- 线上验证：hero 仅剩 Email/GitHub/下载简历；详情页 200；CSS 修复生效
- 隐患：站点实际走 HTTP（nginx 仅配置 80 端口，443 未配置导致证书域名不匹配），已记录待用户决策
- 安全：`.workbuddy/`（含服务器密码的 memory 文件）已加入 .gitignore

## 工程复盘

1. **响应式样式同样需要作用域意识**：媒体查询改变的是"特定断点下的规则集合"，而非"该断点专属的样式"；未覆盖断点下，规则中的属性会以默认值参与布局
2. **布局问题先看结构再调数值**：逐一标注 flex 子项，可快速发现"透明占位"类问题
3. **部署即验证**：每次部署顺手检查线上表现与基础设施（HTTPS/证书），能提前暴露隐性风险
